Jira & Xray Entegrasyonu
Tıklanabilir Doğrudan Linkler

1 Ürün Özeti

YAFI Regression Planner, QA ekibinin koşturacağı regresyon testlerini Jira'dan otomatik oluşturan, Fonksiyonel test senaryolarını Epic/Parent bazlı kümülatif döngü ve rastgele karıştırma (random.shuffle) algoritması ile RC {fixVersion} Functional-1..N formatında "Test Execution" paketlerine bölen ve belirlenen 3 özel Non-Functional testi (YFMTEST-3997, YFMTEST-4007, YFMTEST-4013) RC {fixVersion} Non-Functional-1..N formatındaki paketlere aktaran bir otomasyon aracıdır.

Tüm oluşturulan Test Execution paketleri otomatik olarak standart açıklama şablonuyla açılan ortak bir Test Planına (RC Plan {fixVersion}) bağlanır. Hem Dify ekranında hem de Teams kanalında tüm paketler doğrudan tıklanabilir Jira bağlantıları olarak paylaşılır.

2 Tıklanabilir Doğrudan Jira Bağlantıları

Sonuç ekranında ve Teams bildirimlerinde oluşturulan her issue için doğrudan Jira bağlantısı oluşturulur:

  • Test Plan Linki: https://commencis.atlassian.net/browse/{plan_key}
  • Fonksiyonel Execution Linkleri: https://commencis.atlassian.net/browse/{func_key}
  • Non-Functional Execution Linkleri: https://commencis.atlassian.net/browse/{non_func_key}

Doğrudan Erişim:
Dify sonuç ekranındaki veya Teams mesajındaki mavi bağlantılara tıklayarak ilgili Test Planı veya Test Execution paketini tek tıkla tarayıcınızda açabilirsiniz.

3 JQL Sorguları ve Test Çekme Kuralları

İş akışı aşağıdaki JQL sorgularını kullanır:

1. Fonksiyonel Test JQL Sorgusu:

project in ("YFMTEST", "ISCEPTEST") and issuetype = Test and labels NOT IN ("NonFunctional", "Trash") ORDER BY key DESC

2. Non-Functional Test JQL Sorgusu:

key in ("YFMTEST-3997", "YFMTEST-4007", "YFMTEST-4013") ORDER BY key DESC

4 5 Adımlı Test Dağıtım Algoritması

  1. Epic/Parent Gruplama: Parent/Epic (`customfield_10008` veya `parent.key`) bazında gruplanır.
  2. Epic İçi Karıştırma: Her Epic grubu kendi içinde `random.shuffle()` ile karıştırılır.
  3. Epic Sıralaması Karıştırma: Epic gruplarının sırası rastgele karıştırılır.
  4. Kümülatif Round-Robin Dağıtım: Her turda her Epic'ten 1 test çekilerek paketlere aktarılır.
  5. Non-Functional Sabit Kopyalama: 3 özel Non-Functional test, tüm Non-Functional paketlerine eşit şekilde kopyalanır.

5 Test Plan Açıklama Şablonu (Description Template)

Jira'da otomatik oluşturulan RC Plan {fixVersion} Test Planının Description alanına standart ekip şablonu (Atlassian Document Format ADF) otomatik eklenir:

  • Test Object Data: Build No, Revision No, Build Name
  • Test Environment Data: Server URL, MW Version (Build No), MW Revision No, Endpoint
  • Release Notes*: Sürüm detayları, Hotfix kök nedenleri ve Backup paket açıklamaları
  • Purpose of Test*: Test koşum amacı
  • Test Notes*: Önemli notlar ve bulgular
  • JIRA Issues*: İlgili Jira issue bağlantıları

6 İsimlendirme Standartları

Paket Tipi İsimlendirme Formatı Örnek (fixVersion = 1.2.3)
Ana Test Planı RC Plan {fixVersion} RC Plan 1.2.3
Fonksiyonel Executions RC {fixVersion} Functional-{i} RC 1.2.3 Functional-1, RC 1.2.3 Functional-2
Non-Functional Executions RC {fixVersion} Non-Functional-{j} RC 1.2.3 Non-Functional-1, RC 1.2.3 Non-Functional-2

7 Kullanım Parametreleri ve Ortam Değişkenleri

Girdi Parametreleri (Start Node Inputs):

  • FixVersion: Placeholder: 1.0.0
  • Fonk.Koşum Set Sayısı: Placeholder: Set Sayısı
  • Case Sayısı: Placeholder: Case sayısı
  • Non-Func.Koşum Set Sayısı: Default: 2

Ortam Değişkenleri (Environment Variables):

  • jira_auth: Jira Basic Auth Token
  • xray_client_id: Xray Client ID
  • xray_client_secret: Xray Client Secret
  • teamsWebhookUrl: MS Teams Webhook URL *(Opsiyonel)*

8 MS Teams Webhook Kurulumu ve Kullanımı

  1. Teams grubunuzda Workflows sayfasına gidin.
  2. "Send webhook alerts to YaFi Only QA" akışını seçin.
  3. "Copy webhook link" butonuna tıklayarak adresi kopyalayın.
  4. Kopyaladığınız adresi Dify Çevre Değişkenleri (`teamsWebhookUrl`) alanına yapıştırın.
